# 本科毕业设计开题报告（粗稿）

**论文题目：**资源受限环境下大语言模型长文本推理的 $KV$ Cache 压缩与优化方法研究

## 1. 选题背景与研究意义

### 1.1 大模型长文本推理的显存瓶颈

大语言模型通常以自回归方式生成文本。在 Prefill 阶段，模型对输入 prompt 并行计算各层注意力表示；在 Decode 阶段，每生成一个新 token，模型均需利用当前查询向量与全部历史键、值向量进行注意力计算。为避免在每一步重复计算历史 token 的键和值，推理系统将其保存在 $K_{\text{cache}}$ 和 $V_{\text{cache}}$ 中。该机制降低了重复计算量，但使缓存容量随上下文长度持续增长。

设批大小为 $B$，网络层数为 $N$，序列长度为 $S$，KV head 数为 $H_{kv}$，单个 attention head 的维度为 $d_k$，每个缓存元素的存储位宽为 $p$。忽略页表、对齐和尺度元数据时，一份高精度 $KV$ Cache 的理论存储开销为：

$$
M_{KV}=2BNSH_{kv}d_k\cdot\frac{p}{8}\ \text{bytes}.
$$

其中，系数 $2$ 分别对应键缓存和值缓存。固定模型结构与批大小后，$M_{KV}$ 对 $S$ 呈线性增长；当上下文扩展至数万 token 甚至更长时，缓存会从辅助状态转变为显存配置的主导项。若采用分组查询注意力（Grouped-Query Attention，GQA），$H_{kv}$ 可小于 attention head 数 $H$，但在多层、长序列和多请求并发条件下，缓存仍会形成显著的累积开销。

Decode 阶段具有访存受限特征：经过 $T$ 个生成步后，当前查询仅包含少量新 token，却需读取长度约为 $S+T-1$ 的历史 $K_{\text{cache}}$ 与 $V_{\text{cache}}$。低比特表示可减少读取字节数，但尺度读取、解包和分支控制也会增加开销。因此，本课题以质量、显存与 Decode 效率的联合约束为设计依据。

长文档问答、代码分析和多轮对话依赖长上下文；压缩缓存可提升有限显存下的部署能力。

### 1.2 单一缓存压缩技术的局限性与协同优化的必要性

现有方法通常分别从减少缓存 token 数或降低单元素位宽入手。滑动窗口与重要性淘汰能够直接限制缓存长度，但被删除状态无法恢复，且效果依赖保留策略能否识别后续生成所需的信息；统一位宽量化保留全部 token，却隐含“不同缓存区域具有相近数值分布与误差敏感度”的假设。实际推理中，键和值的作用不同：键量化误差先改变注意力分数，再经 Softmax 函数影响注意力权重；值量化误差则直接累积至注意力输出。不同层、attention head、通道和 token 位置的统计分布与重要性也可能不同。因此，单独依赖淘汰或统一量化都难以同时兼顾容量、质量与访问效率。

现有压缩方法还常在精度、元数据和运行时开销之间存在张力。更细粒度的按通道或 per-token 量化能够更贴合局部范围，却需要额外存储尺度 $S_q$、零点 $Z_q$ 或分组索引；异常值旁路与 Attention Sink 保护能够降低关键状态失真，却会增加非连续访问和实现复杂度。特别是在 Continuous Batching 场景中，缓存选择、追加、页面分配和请求回收同时发生，若数据布局与策略割裂，理论压缩收益可能被索引、元数据、反量化和控制流开销抵消。

本课题据此将缓存保留与混合精度编码置于同一决策过程：高重要性 token 优先保留，高风险组采用较高位宽，低优先级或低风险组采用低位宽或受控淘汰，并对异常值与 Attention Sink 设置保护。该策略可表述为在给定显存容量 $C$ 和可接受时延增量 $\delta_t$ 下，联合优化位宽策略 $\mathcal{P}_b$ 与缓存保留策略 $\mathcal{R}$：

$$
\min_{\mathcal{P}_b,\mathcal{R}}\ \mathcal{L}_{\mathrm{err}}(\mathcal{P}_b,\mathcal{R}),\quad
\mathrm{s.t.}\quad M(\mathcal{P}_b,\mathcal{R})\le C,\ \Delta t(\mathcal{P}_b,\mathcal{R})\le\delta_t.
$$

其中，$\mathcal{P}_b$ 表示量化组到位宽的映射，$\mathcal{R}$ 决定 token 或分组的保留、压缩与淘汰状态。该表述将容量压缩、数值编码和系统实现置于同一优化框架，为后续重要性建模、联合决策、误差分析和内存管理提供统一目标。

## 2. 国内外研究现状

### 2.1 $KV$ Cache 稀疏化与淘汰机制研究

缓存稀疏化与淘汰机制通过仅保留部分历史 token 的键和值来压缩状态规模。StreamingLLM 研究了滑动窗口注意力在超出缓存容量后出现的性能退化，并指出保留初始 token 形成的 Attention Sink 有助于稳定流式推理，因此采用“Attention Sink token 加最近窗口”的保留结构 [@xiao2024efficient]。该类方法的优点是缓存规模可被直接限制，但它依赖 token 重要性的结构性假设；当被淘汰内容承载后续推理所需的细节信息时，信息损失难以仅通过底层实现优化弥补。

$H_2O$ 将缓存淘汰视为动态保留问题，依据注意力贡献保留 Heavy Hitter token，并与近期 token 共同组成受限缓存 [@zhang2023h2o]。该思路能保留非局部重要历史状态，但效果受重要性估计与任务结构影响。

SnapKV 观察 prompt 尾部窗口所呈现的注意力模式，并据此为每个 attention head 选择聚集的重要缓存位置 [@li2024snapkv]。该方法体现了不同 attention head 之间的选择差异，适合讨论“缓存是否应整体等价处理”的问题。然而，淘汰类方法本质上删除状态，难以对被删除 token 的数值信息提供误差界；其性能还取决于观察窗口对后续生成需求的代表性。

稀疏化与量化分别作用于“缓存多少状态”和“如何编码已保留状态”两个维度。本课题不再将选择性淘汰作为未来接口，而是将滑动窗口、重要 token 保留和受控淘汰纳入联合策略；对被保留的缓存状态再依据统计风险和量化敏感度分配位宽，并显式评估两类误差的叠加效应。

### 2.2 $KV$ Cache 低比特量化技术研究

低比特量化通过将浮点缓存映射至有限整数集合降低存储和带宽压力。KIVI 对常见模型的缓存元素分布进行分析，提出键缓存采用 per-channel 量化、值缓存采用 per-token 量化的非对称设计，并以硬件友好的方式实现低比特缓存 [@liu2024kivi]。该工作表明 $K_{\text{cache}}$ 与 $V_{\text{cache}}$ 不宜强制采用相同粒度，也为本课题中的 K/V 非对称策略提供了直接参照。

KVQuant 面向更低比特量化中的分布失真问题，综合采用按通道键量化、旋转位置编码前的键量化、层敏感度加权的非均匀数据类型，以及按向量的稠密—稀疏异常值处理 [@hooper2024kvquant]。其中，按向量隔离异常值可避免少量高幅值元素主导整组量化范围；层级敏感度设计说明不同层对量化误差的容忍度不同。该方案的启示在于，量化精度、异常值处理和层敏感度不应割裂设计。

现有量化方法仍存在三个值得进一步研究的方面。第一，许多策略以离线校准的静态配置为主，对不同请求长度、不同 token 位置和在线缓存追加过程中的分布漂移适应有限。第二，细粒度尺度和异常值元数据会占用额外显存，若忽略该部分，理论压缩率与系统实测值可能不一致。第三，低比特数据的读取效率依赖 kernel 实现，若反量化不能与注意力计算融合，实际 Decode 时延可能无法受益。上述问题构成本课题从“量化机制—缓存布局—算子路径”一体化展开研究的依据。

### 2.3 $KV$ Cache 内存管理与推理系统优化

除算法层压缩外，动态请求中的缓存分配、映射与访问路径也会影响实际收益。PagedAttention 将操作系统分页思想引入 KV Cache 管理，以固定大小的 block 组织非连续物理缓存，并由 vLLM 在请求间实现灵活映射与共享，从而降低碎片和冗余复制 [@kwon2023pagedattention]。该工作说明缓存容量优化不能只计算数据位宽，还需考虑物理布局、block table、请求生命周期及 Continuous Batching 调度。

对于选择与混合精度协同的缓存，系统还需处理可变保留位置、不同位宽数据、尺度与异常值索引。若直接在读取阶段恢复完整高精度张量，可能产生额外临时显存和全局内存流量；若采用过细的分组，又可能因元数据访问和分支发散降低吞吐量。因此，本课题将在 Paged KV Cache 基础上设计压缩 page 布局和逻辑位置映射，并评估融合反量化注意力与动态请求管理对端到端性能的影响。

## 3. 研究内容与技术路线

### 3.1 核心研究目标

本课题拟构建区分层、$K/V$ 类型、attention head、通道与 token block 差异的重要性和风险描述；在显存预算下联合决定缓存保留状态与量化位宽；实现支持压缩追加、位置索引、Paged KV Cache 管理、融合反量化和动态回收的缓存格式；并与全量高精度、窗口淘汰、重要性淘汰及统一量化基线比较模型质量、峰值显存、时延与吞吐量。所有结论以可复现实测数据为准。

### 3.2 拟解决的关键技术

#### 3.2.1 误差与层级敏感度感知建模机制

设 $X_g$ 为某一层、某一类型缓存中的候选组 $g$。拟将局部动态范围、方差、输出敏感度与缓存重要性共同构造风险得分：

$$
r_g=\alpha\,\mathrm{range}(X_g)+\beta\,\mathrm{var}(X_g)+\gamma\,\mathrm{sens}(X_g)+\eta\,\mathrm{imp}(X_g).
$$

其中，$\alpha$、$\beta$、$\gamma$ 和 $\eta$ 为校准的非负权重。对于注意力输出 $Y=AV$，键和值误差可作一阶近似：

$$
\Delta Y\approx \Delta A\,V+A\,\Delta V.
$$

该式表明，$K_{\text{cache}}$ 的扰动经 $\Delta A$ 间接影响输出，$V_{\text{cache}}$ 的扰动则以 $A\Delta V$ 直接叠加。拟据此分别统计键和值风险，并结合历史注意力贡献、位置特征与近期窗口形成缓存保留优先级；模型的有效性以重构误差、困惑度和长文本任务指标验证。

#### 3.2.2 缓存选择与 Key-Value 非对称混合精度协同策略

对于组 $g$ 内实数张量 $X_g$，拟使用带尺度与零点的线性非对称量化。令 $x_{\min,g}$ 和 $x_{\max,g}$ 分别为组内最小值和最大值，整数表示范围为 $[q_{\min},q_{\max}]$，则量化尺度与零点可定义为：

$$
S_{q,g}=\frac{x_{\max,g}-x_{\min,g}}{q_{\max}-q_{\min}},\qquad
Z_{q,g}=\mathrm{clip}\!\left(\mathrm{round}\!\left(q_{\min}-\frac{x_{\min,g}}{S_{q,g}}\right),q_{\min},q_{\max}\right).
$$

相应的量化与反量化过程为：

$$
q_g=\mathrm{clip}\!\left(\mathrm{round}\!\left(\frac{X_g}{S_{q,g}}\right)+Z_{q,g},q_{\min},q_{\max}\right),\qquad
\hat{X}_g=S_{q,g}(q_g-Z_{q,g}).
$$

在不发生截断饱和的理想条件下，舍入误差满足：

$$
\|X_g-\hat{X}_g\|_{\infty}\le\frac{S_{q,g}}{2}.
$$

联合决策首先由 $\mathcal{R}$ 根据缓存重要性、近期性和 Attention Sink 保护规则确定保留、压缩或淘汰状态；随后以风险 $r_g$ 将保留组映射到 $b_{\text{low}}$、$b_{\text{mid}}$ 与 $b_{\text{high}}$ 三档位宽，即 $b_g=\mathcal{P}_b(r_g)$。键缓存优先考察 per-channel 或 channel-wise 分组量化，值缓存优先考察 per-token 或 token-block 量化；对满足 $|x|>\tau$ 或高敏感度条件的元素集合 $\mathcal{O}$，采用高精度旁路或独立尺度。该策略的压缩收益必须扣除位置索引、保留标识、尺度、零点、位宽标识与异常值索引开销：

$$
M_{\text{mixed}}=\sum_{g\in\mathcal{G}}\frac{|g|b_g}{8}+M_{\text{meta}}+M_{\text{outlier}}.
$$

#### 3.2.3 支持选择与混合精度的压缩 Cache 内存管理机制

系统层面拟将缓存组织为具有固定 token 容量的 page，每个 page 保存保留位置索引、量化 $K/V$ 数据、量化参数、位宽描述和异常值索引；策略更新时维护逻辑位置到物理 page 的映射，当前 page 写满后分配新 page，请求结束后回收。注意力路径依据保留索引读取压缩状态，并融合解包、尺度加载、反量化与点积，避免生成完整临时高精度缓存。正确性通过缓存选择、追加一致性、淘汰与保留切换、反量化误差、page 边界和混合请求测试验证。

### 3.3 总体技术路线图说明

本课题遵循“重要性与统计分析—保留/位宽联合决策—在线执行—实验反馈”的闭环。首先采集各层 $K_{\text{cache}}$ 与 $V_{\text{cache}}$ 的注意力贡献、位置、范围、方差、异常值及敏感度特征；其次确定缓存保留优先级、量化粒度、位宽和保护规则；随后将该策略接入 Prefill 和 Decode 过程，在缓存写入与策略更新时完成选择和量化，在注意力读取时依据位置索引融合反量化；最后以实验结果反向评估策略误差与实现开销。

```text
校准数据与模型配置
        |
        v
缓存统计与重要性采样 -> 保留优先级/风险评分 -> 选择、位宽与保护规则
        |                                           |
        |                                           v
        +-----------------------------------> 策略配置表
                                                    |
                                                    v
Prefill：生成 K/V -> 选择与在线量化写入 -> Paged KV Cache 管理
                                                    |
                                                    v
Decode：查询 Q -> 索引读取/融合反量化注意力 -> 注意力输出
                                               |
                                               v
质量、显存、时延测试 -> 消融分析 -> 策略修订
```

该路线将算法层的联合决策与工程层的数据布局对应起来：重要性模型决定“保留哪些状态”，风险模型决定“对保留状态使用何种位宽”，缓存管理决定“如何保存并定位压缩数据”，融合算子决定“如何在读取时控制索引与反量化开销”。

## 4. 实验方案与评测指标

### 4.1 实验平台与基线模型

拟选取 Qwen2.5 与 Llama-3 系列中能够在实验设备复现的公开模型。平台将记录 $GPU$ 型号及显存、驱动与 $CUDA$ 版本、推理框架、PyTorch、精度模式、随机种子和最大上下文长度；具体配置填为 `[待填数据: 硬件与软件版本]`。

基线至少包括：高精度全量 $KV$ Cache、滑动窗口、重要性驱动淘汰、统一 $8$ 位量化、统一 $4$ 位量化，以及在条件允许时复现的代表性选择或量化方法。另设置“仅选择”“仅混合位宽”和“选择与混合位宽协同”配置，区分 token 数量压缩与数值表示压缩的贡献。所有方法应采用相同模型权重、prompt、生成参数、缓存预算、批大小 $B$ 和序列长度 $S$；若某基线因实现约束无法完全复现，应单独说明版本、差异与排除原因。

### 4.2 数据集与评估基准

WikiText-2 用于语言建模困惑度评估，且评测应覆盖缓存写入与后续读取。Needle In A Haystack 在不同上下文长度和插入深度下放置可验证事实，结果以位置—长度二维图展示，考察长文本召回的空间差异。

LongBench 覆盖多任务、双语长上下文理解，可检验问答、摘要、代码和合成任务的泛化表现 [@bai2024longbench]。不同任务遵循官方处理与指标定义，并记录数据版本、截断规则和 Decode 设置。

### 4.3 评测指标

显存峰值降低率用于衡量方法相对高精度基线的实际显存节省：

$$
\rho_M=\frac{M_{\text{FP}}-M_{\text{method}}}{M_{\text{FP}}}\times100\%.
$$

其中，$M_{\text{method}}$ 应包含保留的缓存主体、位置与保留元数据、量化参数、异常值旁路和运行时临时张量的实测峰值，避免仅报告理论 token 保留率或位宽压缩率。Decode 吞吐量加速比定义为：

$$
\rho_{\text{decode}}=\frac{\mathrm{Throughput}_{\text{method}}}{\mathrm{Throughput}_{\text{FP}}}.
$$

除吞吐量外，还需分别记录 $t_{\text{prefill}}$ 与单步 $t_{\text{decode}}$，以区分 Prefill 计算成本和 Decode 阶段的缓存访问成本。长上下文召回准确率可定义为正确召回样本数与总样本数之比：

$$
\mathrm{Acc}_{\text{recall}}=\frac{N_{\text{correct}}}{N_{\text{total}}}\times100\%.
$$

模型质量指标包括 $\mathrm{PPL}$、$\Delta\mathrm{PPL}$ 与 LongBench 任务得分。实验结果表中的具体数值在实验完成前均使用 `[待填数据: 指标名称、模型、序列长度与方法]` 占位。消融实验将依次移除缓存选择、混合位宽、异常值旁路、Attention Sink 保护、细粒度尺度和融合算子，并比较不同保留预算与位宽阈值下的质量—显存—时延变化，评估各组件的独立贡献及交互效应。
